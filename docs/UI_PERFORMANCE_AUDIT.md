# Compose UI and performance audit — 2026-10-25

## Scope

Reviewed Overview, Courses, Students, Terms, Offerings, Teaching context, Lectures, Question Bank, Exam Builder, Gradebook, Attendance, Activity and Settings, plus shared selectors, tables, record forms, confirmation dialogs, question/exam editors and PDF/Excel overlays. The approved charcoal/violet layout, typography, animations and business rules remain intact. Java services and migration resources are unchanged.

## Confirmed issues and corrections

| Finding | Correction | Regression evidence |
| --- | --- | --- |
| Shared selectors required pointer clicks or repeated Tab presses; arrows/Enter in search did not choose an option | Added Up/Down/Enter/Escape navigation, cursor highlighting, lazy-list scrolling, focus synchronization and an explicit no-match state | 50-option keyboard test selects an off-screen option, searches, handles no matches and dismisses safely |
| A deeply scrolled page left the next destination scrolled past its heading/actions | Reset the shell scroll only when destination changes; theme changes and edits do not reset it | Scroll/navigation test also verifies unchanged position on theme switch |
| Gradebook recalculated all grade results/statistics on unrelated recompositions | Cache the existing Java calculation result with derived state tied to draft revision | Repeated reads retain one result; zero, invalid edits and discard correctly invalidate it |
| Attendance recalculated the saved course summary during local marking/search | Remember the saved summary by immutable book; a successful refresh replaces it | Existing attendance percentage/save/restart tests |
| Dashboard fetched the offering list then one joined summary per offering | Use the existing batch summaries service and sort by ID to preserve the original ordering/fallback selection | Compare all labels/order and explicit/missing selections against original service reads |
| Sidebar indicator position was read during composition on every spring frame | Read its animated offset in the placement lambda | Existing intermediate/settled/idle animation tests |
| A long offering label could crowd out Gradebook save status | Give the context label bounded remaining width and spacing | Existing minimum-size gradebook captures and audit matrix |
| Sortable record-table headers lacked visible keyboard focus | Add palette-based focus borders and respect disabled controls | Shared control inspection; existing table interaction suites |
| Empty offering picker referred to the removed “full workspace” | Point to the existing Offerings destination | Empty workspace rendering tests |

## Verification and interpretation

The new audit suite renders all 13 routes at 864 × 621 logical content units, in Light and Dark palettes at density 1.0 and simulated 1.5. It produces 52 `audit-*` screenshots under ignored `prototype-compose/build/screenshots`. This covers scaled Compose layout, not Windows monitor changes. The existing suites cover normal/minimum feature layouts, Arabic content, editor validation, keyboard traversal, document previews, unsaved guards, database reconstruction and PDF/Excel contents.

Performance evidence is structural and deterministic: offering summaries now require one joined service query instead of the list plus one query per offering; unchanged grade drafts reuse the same calculated result across 100 reads. No grading arithmetic was rewritten. Sidebar placement no longer requires composition for each indicator offset. Existing frame-clock tests verify movement, settling and idle pixels. Screenshot readback timings are not FPS and are not presented as a GPU benchmark.

The running application is checked using the isolated synthetic `prototype-compose/build/native-ui-audit` database, generated by the audit test. Production integrity is checked read-only against a before/after hash and migration-history baseline. Test fixtures are never inserted into the user's database.

## Remaining limitations

- Windows multi-monitor transitions, OS DPI changes, screen-reader coverage and physical keyboard input still require manual hardware testing. Injected native input and simulated density do not replace these checks.
- All modules are still loaded on a workspace refresh. Very large institutional datasets and worst-case document/large exam composition memory use were not benchmarked; no speculative lazy-loading redesign was introduced.
- The screen shell and bounded tables deliberately have separate vertical scrolling areas. Native wheel/keyboard checks cover the tested configurations, not every touchpad/device combination.
- Arabic shaping is supported, but the application is not fully localized or mirrored RTL. Existing PDF typography limitations remain.
- Native Microsoft Excel interoperability is outside this UI audit; existing POI/PDFBox content regression tests remain authoritative for generated files.
